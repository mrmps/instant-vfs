instant-vfs · hybrid code search

Every repo indexes itself in seconds: potion-code embeddings + BM25 in the Durable Object, Jev on top, dozens of repos per call

Branch hybrid-search (on top of semantic-jev) · deployed to gitvfs.miryaboy.workers.dev · 220 tests green

12 cold repos ingested, indexed, searched and reranked in one 2.9s call

What changed

  • GET /<owner>/<repo>/search?q= — hybrid code search. Symbol-aware chunks (one per outline symbol, 40-line windows elsewhere) are embedded with Minish Lab's potion-code-16M-v2 and scored with BM25; the two lists are fused by reciprocal rank (the semble recipe), then Jev reranks the top 30 and adds relevance. &classify=a,b,c labels every hit, &type=code|docs restricts, &glob= scopes, &rerank=0 is pure retrieval.
  • GET /search?q=&repos=o/a,o/b@ref,… (base URL, up to 20 repos) — each repo is resolved, ingested and indexed concurrently, per-repo tops are merged, reranked together, and diversified (≤2 hits per file, no repo takes more than half the slots). Repos still warming are listed under pending.
  • Embedding runs in the Worker. src/embed.ts is a dependency-free port of Model2Vec inference (BERT WordPiece → mean pool → L2 norm), pinned to the Python reference token-for-token by test/embed.test.ts. Weights are a 17MB int8 export (bench/export-model.py, cosine 0.9999 to fp16) in R2, loaded once per isolate.
  • Every repo indexes itself. After ingest the DO schedules an alarm that builds the index in 20s slices (hono ≈1s, vite ≈3s, react 41k chunks ≈6s). /find folds the top hybrid hits in as candidates whenever the index is ready.
  • Translated docs collapse onto one page; prose is down-weighted 0.8× against code; tests, fixtures, .d.ts and snapshots 0.7×.

Review focus

  • src/embed.ts — the tokenizer must stay byte-for-byte compatible with HF WordPiece; the test compares against potion-ref.json generated by model2vec.
  • src/repo-do.ts — ensureIndexed is resumable and the alarm now multiplexes index slices with eviction; index_pending is the hand-off.
  • src/search-index.ts — all ranking constants are explicit (RRF k=60, symbol ×1.15, docs ×0.8, tests ×0.7, symbol-like queries lexical 1.4×).
  • Memory: react's matrix is 41k×256 int8 ≈ 10MB per DO plus the 17MB model per isolate.

Files

  • src/embed.ts — Model2Vec inference port + int8 model loader.
  • src/search-index.ts — chunking, BM25 terms, in-memory matrix, fusion, diversity.
  • src/repo-do.ts — chunks table, ensureIndexed, search, background build via alarm.
  • src/worker.ts — /search (per repo), /search?repos=, rerank/classify, /find integration, /status.index.
  • bench/export-model.py, wrangler.toml (MODELS R2 bucket).
  • Tests: test/embed.test.ts (5), test/search.test.ts (12). Live tests now fail loudly on a 503 unless GITVFS_ALLOW_UNAVAILABLE=1.
  • Docs: llms.txt, both landings, README, functionality.md; bench prompt + tasks T16–T18.

Operational

  • New R2 bucket gitvfs-models with potion-code-16M-v2.m2v (upload with --remote; wrangler 4 defaults to local, which is how the first deploy shipped with search silently unavailable).
  • Without the bucket: 503 search_unavailable. Without the TypeSafe key: retrieval works, ranked: false.
  • Search shares the /grep+/bash per-IP limit; cross-repo calls count once.
