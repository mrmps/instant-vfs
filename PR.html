What changed

The live service advertised GET, HEAD, and OPTIONS, but write-shaped verbs fell through to the read router and returned 200. A global method guard now returns 405 method_not_allowed before any repository work.

  • POST, PUT, PATCH, and DELETE are rejected.
  • The response includes Allow: GET, HEAD, OPTIONS.
  • The JSON error lists the supported methods for API clients.
  • CORS and security headers remain consistent with other errors.

Request flow

Review focus

  • Confirm the guard belongs before rate limiting and routing.
  • Confirm the canonical error and Allow header are sufficient for clients.
  • Confirm GET, HEAD, and preflight behavior remain unchanged.

Implementation

src/worker.ts

One shared allow-list drives both CORS metadata and runtime enforcement, preventing the two contracts from drifting.

const ALLOWED_HTTP_METHODS = ["GET", "HEAD", "OPTIONS"];

if (request.method === "OPTIONS") {
  return corsPreflight(request);
}

if (request.method !== "GET" && request.method !== "HEAD") {
  return 405;
}
