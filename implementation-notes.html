Implementation Notes

Running notes for decisions, tradeoffs, deviations, and open questions in instant-vfs.

Better Agent Harness Investigation

The current bench/agents harness is a custom agent evaluation loop, not a Better Agent app. It directly calls the Anthropic Messages API, defines one http_get tool, executes model-request/tool-result iterations, grades the final answer deterministically, and persists trace artifacts.

Better Agent's documented run model is higher level: defineAgent, register agents with betterAgent({ agents }), then call app.agent(name).run() or .stream(). Source review shows that this wraps context validation, optional memory/thread persistence, plugin hooks, abort handling, runtime creation, model calls, tool execution, interruptions, state, and final run records.

  • Design decision: keep the existing harness custom unless the goal becomes validating Better Agent itself. It is small, deterministic, and optimized for paired gitvfs measurements.
  • Tradeoff: Better Agent would provide typed tools, reusable run/stream plumbing, hooks, and persistence. It would also add framework behavior that the benchmark does not currently need.
  • Open question: whether future benchmark work should add a Better Agent condition to measure framework integration, or keep all conditions on the same minimal Anthropic loop for cleaner gitvfs attribution.

Human Landing Page

The root route now serves a minimal browser UI when the request accepts text/html. Humans get one clear explanation, one repository field, and one prompt to copy into an agent. Raw clients still receive the complete text reference, and /llms.txt remains the stable agent contract.

The page is rendered directly by the Worker with inline CSS and a small prompt generator. It adds no frontend framework, build pipeline, font request, image asset, or API mutation.

  • Design decision: use the Accept header instead of user-agent sniffing. Browsers already request HTML, while curl and programmatic clients normally request raw content.
  • Compatibility decision: ?format=html and ?format=text make either representation explicit for tests, debugging, and unusual clients.
  • Tradeoff: the UI intentionally teaches the recommended agent workflow rather than exposing every endpoint. The complete catalog stays one click away in /llms.txt.
  • Reference influence: React Doctor informed the direct outcome-first headline and immediate action; React Review informed the narrow reading width, neutral palette, and quiet bordered surfaces.

Endpoint Semantics Fixes

The file endpoints now share one logical line-count convention: a trailing final newline terminates the previous line and does not create a blank line. The worker keeps the existing stored byte-count logic, then applies matching logical splitting in line slices, numbered output, outlines, and grep context.

CORS preflight is handled before repo routing and rate-limit checks. This keeps browser clients from accidentally resolving refs or reading file bodies when they only asked for OPTIONS metadata.

The same global request gate now rejects every method other than GET, HEAD, and OPTIONS before routing. This closes the gap where write-shaped verbs were processed as reads despite the advertised CORS contract.

  • Design decision: out-of-range ?lines= requests return 416 line_range_not_satisfiable instead of an empty 200 response, because the caller asked for a specific file range that does not exist.
  • Design decision: /bash maps shell non-zero exits to non-2xx HTTP statuses while preserving x-gitvfs-exit-code and text output. Unknown commands use 400, timeouts use 504, and supported command failures use 422.
  • Tradeoff: a grep no-match inside /bash is now HTTP 422 even though the shell runner completed normally. This favors API clients that depend on HTTP status over clients that only inspect shell output.
  • Design decision: unsupported methods return the canonical JSON error shape plus Allow: GET, HEAD, OPTIONS. The guard runs before rate limiting and repo resolution so a rejected verb cannot spend repository work or populate cache.
